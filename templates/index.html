A LITTLE CONTEXT GOES A LONG WAY

Grammar & Help

Understand the rules, common mistakes, and the machine that checks them.

What is an assignment statement?

It gives a value to a named variable. In this project, the statement declares an integer and uses an arithmetic expression.

int total = 8 + 5;

int is the keyword, total is the name, and 8 + 5 is the expression.

What makes it valid?

  • Start with the exact keyword int, followed by a space or tab.
  • Use a name that starts with an ASCII letter or underscore.
  • Add =, then whole numbers with at least one operation.
  • Use only + - * / and finish with one ;.
  • Never divide by an all-zero number, such as 0 or 00.

The supported grammar

assignment ::= int identifier = expression ;
identifier ::= (letter | _) {letter | digit | _}
expression ::= integer operator integer
               {operator integer}
integer    ::= digit {digit}
operator   ::= + | - | * | /

Spaces or tabs are required after int and optional elsewhere between tokens, including before and after the statement. They cannot split a name or number.

Names use A–Z, a–z, 0–9, and _. Numbers use 0–9; leading zeros are allowed. The name int is permitted by this restricted grammar.

This is a small teaching grammar, not the full Python or C language. Line breaks, variables on the right, unary signs, parentheses, decimals, comments, and multiple statements are not supported.

Regular Expression

This expression describes the complete assignment syntax. Match the entire input using Python re.fullmatch.

{{ syntax_regex }}
  • int[ \t]+ requires lowercase int followed by a space or tab.
  • [A-Za-z_][A-Za-z_0-9]* describes an identifier.
  • [0-9]+ describes an unsigned integer.
  • (?:...)+ requires at least one arithmetic operator and another integer.
  • ; terminates the statement; spaces and tabs may separate tokens.

The expression checks syntax. Division by an all-zero integer is rejected separately by the semantic checker, so int a=8/00; matches the syntax but is invalid overall. The application's recognizer uses its DFA.

Common mistakes

int a = 8;

Include an operation, such as 8 + 5.

int a = 5++5;

Put a number after each operator.

int a = 8/00;

Do not divide by zero. 8/05 is allowed.

int a = 5+5

Finish with a semicolon: ;.

Deterministic Finite Automaton (DFA)

A deterministic finite automaton (DFA) follows exactly one next state for each state and token category. The tokenizer splits the input; the DFA follows its transition table; a separate semantic check then looks for literal division by zero. No input is executed.

The diagram shows Start, States 2–7, Final, and Deadlock. These correspond to A, B–G, H, and DEAD in the engine trace. Final is the only accepting state, and the input must end correctly before syntax is accepted. Deadlock rejects a token that cannot follow the rules. Double circles mark accepting states. The int token includes its required space or tab. Names and numbers are read one character at a time. E reads the first integer; G reads later integers. Both loop on digits.

Frequently asked questions

Why does “int a = 8;” fail?

The project grammar requires at least one arithmetic operator and two integer operands. Try int a = 8 + 0;.

Why can a rejected statement end at H?

H with a completed input means the syntax is valid. A separate semantic check can still reject division by zero. The diagram remains faithful to the syntax check.

Does it calculate the answer?

No. It checks the grammar and literal zero divisors. It does not evaluate arithmetic, check overflow, or apply full programming-language semantics.

Where does my input go?

Only to the Python server on your computer. There are no external requests, uploads, analytics, or online fonts.
